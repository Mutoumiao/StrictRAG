# 04 · dec：裁定 —— KB 内 role 是否参与闸（本图枢轴）

Type: grilling
Status: open
Blocked by: 01, 02, 03

## 要裁什么

一句话：**现行源码「KB 内授权只看成员资格 + 权限码、完全不看 `kb_members.role`」，与 ADR-045 焊死 #1/#3、ADR-035 §决策 5/§决策 7 的 role 条件，是「缺口」还是「已被 ADR-051 取代」？**

三种可能去向，必须择一，并写清证据链：

| 去向 | 落地动作 |
|------|----------|
| **A · 缺口** | 源码补 role 闸（只加严）→ 工单 05 |
| **B · 已被取代** | 源码不动；镜像侧记「条款仍在、判据已变、销账须 ADR」→ 工单 06 |
| **C · 分层裁定** | 逐条裁：某些 role 条件（如删他人文档仅 admin）仍有效 → 补源码；另一些（如 read 不得上传）已被「码 + 模板」覆盖 → 镜像侧销账 |

## 裁定纪律（不得违反）

1. **证据优先**：只引工单 01/02 里**已核过的原文与行号**，禁止新引未经核实的条款。
2. **不得擅改冻结文本**：`prds/00–11` 一个字不改。若裁定需要改冻结语义 → 只能记债，**不得**直接改 PRD。
3. **只加严不放宽**（ADR-046）：任何源码动作只能是收紧；若某方案会放宽任何既有门禁 → 直接否决。
4. **不翻转默认**：`AUTH_ENFORCE` 等默认值不动；若不改默认就落不了地 → 说明该去向不成立，改选别条。
5. **反证优先**：裁定前必须做**反证实验**——用实测（而非推断）证明「现状确实不查 role」（例如把 role 判定临时插入闸、确认现有测例确有可被 role 拦住的样本；若**没有任何测例**能体现差异，必须实测确认这件事，因为它直接决定去向 A 的可行性与影响面）。
6. **对齐既有姿态规则**（前图已立，不重议）：闸姿态随该入口的权限码姿态；`whenEnforced` 系在 `AUTH_ENFORCE` 关时不查。

## 产出

- 一段裁定正文：去向 + 逐条条款的处置表（条款 → 缺口 / 已覆盖 / 需 ADR 销账 → 证据）。
- 「**没落地的部分**」清单：明确写出哪些条款本次**不**落地及原因。
- 若为去向 A/C：给出**落点清单**（哪些文件、哪些入口），交付工单 05。
- 若为去向 B：给出**镜像措辞**（spec / module-status / coverage 三处各写什么），交付工单 06。

## 验收

裁定正文里每一条结论都能被指到 `文件:行`；反证实验有可复现的命令与观察到的输出；三种去向里被否决的两种也写明否决理由（防止下次重开）。
