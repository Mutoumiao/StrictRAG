## Question

基于工单 01 的现状面，**择一**并给出可执行细则：

1. **选路与理由**：判据必须来自 `prds/07-models`（Gateway 契约）· `prds/08-quality`（mock 禁签字）· 半产品 DoD（HALF-SMOKE 口径）与仓内既有的「宁拒勿妄」设计意图，**不许凭偏好**。若选路 A，必须正面回答「桩会不会削弱『mock chat 非 JSON → 拒答』这条有意设计」，并给出**使它不削弱**的具体机制。
2. **姿态**（路 A 时）：桩的启用方式（新档位 / 当普通 HTTP Gateway 指过去）、生产档位下的行为（拒绝启动？）、标注面（启动 banner / `smoke:half` 输出 / 报告字段）、以及**不允许**出现的地方（签字包 / 准出路径 / `prds`）。
3. **可诊断性细则**（路 B 时，或路 A 作为并列要求）：失败必须给出哪几条信息（缺 Gateway / 缺哪条契约 / 哪一次调用返回了非 JSON / 该去读哪份文档），以及这几条信息落在哪几个文件。
4. **文档落点**：「问答段的环境前置」写进哪几处、按什么顺序让第三人读到；模块状态与雾清单如何如实改（**不许**把「桩跑通」写成「RAG 可用」）。
5. **禁则**：本裁定必须显式列出实现方不许做的事（尤其「不许为让 smoke 变绿而放宽 verify / 引用判定」，以及「不许在生产代码里为桩开后门」）。

**约束**：不改 `prds/00–11`、不改任何门限数字与判定公式、不放宽任何默认开关（新档位只能显式开启且默认关）。
