### 情形 A —— 裁定「等价形态已满足」

- 不改数据形态、不改契约、不改谓词；把「欠债」改成**准确口径**。

- 按裁定落最小实现并回写。

### 对抗性反向复核（本图必守，前图教训）

逐条核「这句话在源码里真能指到吗」：

- 「部门轴走等价结构化支、四条规则逐条兑现」→ 指 `dept-acl.ts`（`effectiveLevel` / `isAncestorPath` / `grantEffectiveLevel` / `isDocVisibleForDeptAcl`）与 `es-sparse.ts`（部门组 + 级别组），研究票 §2.4 已逐函数核实。
- 「用户轴与 `user:{id}` 只差记号、可读集合逐位一致」→ 指 `doc-acl.ts` 的 `includes(userId)` 与 `es-sparse.ts` 的 `term aclPrincipals: uid`；两侧都是精确相等，研究票 §3.1 已核实。
- 「须迁移才能带前缀」→ 指 `packages/db/src/schema/kb/documents.ts` 的 `uuid('acl_principals').array()` 与 `packages/db/drizzle/0014_p3b_acl_principals.sql`；**「写前缀会以何种错误失败」是只读推断、未实跑**，已在债行里以「须 `uuid[] → text[]` 迁移」表述（不主张已实测报错）。
- 「`role:` 非 ADR-057 必达」→ 指 ADR-057 §5 的「至少含」列表只有 `user:{id}` 与 `dept:…:lv:…`；`role:…` 只在 ES PRD（带「等」）与安全 PRD（带「等」）。研究票 §1.1 已逐条引原文。
- 「PRD 05 §2.4 未规定语法」→ 该节逐字只有标题 + 两个 HTTP 行，全文不含 `aclPrincipals`。研究票 §1.2 已核实。
